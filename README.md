# rag_example

A minimal, end-to-end **RAG (Retrieval-Augmented Generation) pipeline with a
tool-calling agent**, built in two Jupyter notebooks on top of LangChain,
FAISS and LangGraph.

Documents (PDF/TXT) are chunked, embedded locally and stored in a FAISS index.
A Groq-hosted LLM then answers questions about them through a LangGraph agent
that can call a document-search tool — plus a few arithmetic tools — and is
instructed to ground every answer in the retrieved context.

## How it works

```
sampledocs/*.pdf,*.txt
        │  PyPDFLoader / plain-text read
        ▼
   text chunks            RecursiveCharacterTextSplitter (size 500, overlap 50)
        │  HuggingFaceEmbeddings — sentence-transformers/all-MiniLM-L6-v2 (local, CPU)
        ▼
   FAISS index            saved to ./faiss_index/
        │  retriever, k=3
        ▼
   search_docs tool ──► LangGraph agent ──► answer
                          llm_call ⇄ tool_node
                          ChatGroq: openai/gpt-oss-20b
```

The agent graph is a two-node loop:

- `llm_call` — sends the system prompt plus message history to the LLM.
- `tool_node` — executes any tool calls the model requested.
- `should_continue` — routes back to `tool_node` while tool calls are pending,
  otherwise ends the run.

Tools available to the agent: `add`, `multiply`, `divide`, and `search_docs`
(vector search over the index).

## Notebooks

| Notebook | What it does |
|---|---|
| `pdf_loader.ipynb` | Loads the PDF from `sampledocs/`, splits it into chunks, embeds them, builds and saves the FAISS index, then builds and runs the agent. |
| `experiment.ipynb` | Builds the index from the TXT file, defines the same tools and agent graph, and exercises the agent end-to-end. |

Run `pdf_loader.ipynb` first if you want an index built from the PDF; the
notebooks are self-contained and either can (re)build `faiss_index/`.

## Requirements

- Python >= 3.12 (developed on 3.14)
- A Groq API key — <https://console.groq.com/keys>
- No GPU required; embeddings run on CPU

Dependencies are declared in `pyproject.toml`: `faiss-cpu`, `langchain`,
`langchain-community`, `langchain-groq`, `langchain-huggingface`, `langgraph`,
`sentence-transformers`, `python-dotenv`, `streamlit`. The lockfile is
`uv.lock`.

## Setup

```bash
# 1. install dependencies (uv is the intended workflow)
uv sync

# 2. create your env file and add your Groq key
cp .env.example .env
#   .env  ->  GROQ_API_KEY=gsk_...

# 3. run the notebooks
uv run jupyter lab
```

Using pip instead:

```bash
python -m venv .venv
source .venv/Scripts/activate     # Windows (git-bash)
pip install -e .
```

## Configuration

Read from `.env` via `python-dotenv` (`load_dotenv()` is called in the first
cell of each notebook):

| Variable | Required | Purpose |
|---|---|---|
| `GROQ_API_KEY` | yes | Auth for `ChatGroq` / `openai/gpt-oss-20b`. Read automatically by LangChain. |
| `Hugging_face_api` | no | Hugging Face token, only needed for gated/private models. The default embedding model runs locally and does not use it. |

## Usage

Inside either notebook, after the agent is compiled:

```python
run_agent("What is artificial intelligence?")
run_agent("What is BananaGraph and how many nodes does it contain?")
run_agent("what is 12 * 7")          # routes to the multiply tool
```

The system prompt requires the agent to call `search_docs` before answering
questions about AI/ML concepts and to answer only from the retrieved context;
arithmetic questions are routed to the math tools.

## Notes

- `faiss_index/` is regenerated by the notebooks and is git-ignored.
- `FAISS.load_local` is called with `allow_dangerous_deserialization=True`,
  which unpickles a local index file. Only load indexes you built yourself.
- Never commit `.env`; it holds your API key. `.env.example` lists the
  variable names with empty values.
